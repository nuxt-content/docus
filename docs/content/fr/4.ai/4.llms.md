Docus intègre `nuxt-llms` par défaut pour préparer votre contenu aux Large Language Models (LLMs). Toutes vos pages de documentation sont injectées et les fichiers `/llms.txt` et `/llms-full.txt` sont automatiquement générés et pré-rendus.

::note{to="/llms.txt"}
Consultez le fichier `/llms.txt` généré pour la documentation Docus elle-même.
::

## Valeurs par défaut

Voici les valeurs par défaut utilisées pour générer le fichier `/llms.txt` :

- `domain` → calculé en fonction de votre plateforme de déploiement (ou via la variable d'environnement `NUXT_SITE_URL`)
- `title` → extrait de votre `package.json`
- `description` → extrait de votre `package.json`
- `full.title` → extrait de votre `package.json`
- `full.description` → extrait de votre `package.json`

## Personnalisation

Vous pouvez surcharger vos données LLMs depuis le `nuxt.config.ts` :

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  llms: {
    domain: 'https://votre-site.com',
    title: 'Nom de votre site',
    description: 'Une brève description de votre site',
    full: {
      title: 'Nom de votre site',
      description: 'Une brève description de votre site',
    },
  },
})
```

### Guider les agents

Vos pages expliquent ce que fait votre produit. Elles disent rarement *quand* y recourir, ce dont un agent a besoin avant de vous recommander. Deux options y répondent :

- `sections` ajoute un groupe de liens avant la liste des pages générée, pour les ressources situées hors de votre contenu (un dépôt, un paquet, une référence d'API)
- `notes` ajoute un bloc `## Notes` à la fin du document, l'endroit adapté aux conseils d'usage

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  llms: {
    domain: 'https://votre-site.com',
    sections: [
      {
        title: 'Developer Resources',
        description: 'Points d\'entrée exploitables par une machine.',
        links: [
          { title: 'Source sur GitHub', description: 'Issues et releases.', href: 'https://github.com/votre-org/votre-repo' },
        ],
      },
    ],
    notes: [
      'Quand utiliser cette librairie : vous construisez X et souhaitez Y.',
      'Cette librairie ne remplace pas Z. Pour cela, utilisez plutôt W.',
      'Lire cette documentation en tant qu\'agent : ajoutez `.md` à toute URL de page, ou envoyez `Accept: text/markdown`.',
    ],
  },
})
```

## 404 adaptées aux agents

Plutôt que de répondre avec un corps d'erreur JSON, Docus renvoie un court document markdown qui liste les points d'entrée exploitables par une machine réellement servis par votre site :

```bash
curl -H "Accept: text/markdown" https://docus.dev/en/does-not-exist
```

```md
---
title: "Page Not Found"
status: 404
---

# 404 Page Not Found

The page `/en/does-not-exist` does not exist on https://docus.dev.

## Where to look next

- [API catalog: every service document this site publishes](https://docus.dev/.well-known/api-catalog)
- [Sitemap (Markdown): every page on the site](https://docus.dev/sitemap.md)
- [MCP server card: MCP endpoint at https://docus.dev/mcp](https://docus.dev/.well-known/mcp/server-card.json)
- [MCP endpoint (streamable HTTP)](https://docus.dev/mcp)
- [llms.txt: index of the documentation for LLMs](https://docus.dev/llms.txt)
- [llms-full.txt: the full documentation as a single file](https://docus.dev/llms-full.txt)
- [Agent skills index: every skill published by this site](https://docus.dev/.well-known/skills/index.json)
- [Agent skill: create-docs](https://docus.dev/.well-known/skills/create-docs/SKILL.md)
- [Agent skill: review-docs](https://docus.dev/.well-known/skills/review-docs/SKILL.md)
- [Sitemap (XML): every page, with its last modification date](https://docus.dev/sitemap.xml)

## Fetching markdown

Any documentation page is available as markdown: append `.md` to its URL
or send `Accept: text/markdown`.
```

Ces liens proviennent du même registre que l'en-tête `Link` de votre page d'accueil et `/.well-known/api-catalog`, si bien que le document ne pointe jamais vers une route inexistante : les entrées de skills n'apparaissent que si votre site [publie des skills](/fr/ai/skills), et `/llms-full.txt` uniquement si le fichier est activé.

La réponse conserve le statut `404` et est servie en `text/markdown; charset=utf-8` avec `Vary: Accept, User-Agent`, afin que les CDN ne confondent jamais les deux variantes.

Seuls les clients qui n'affichent manifestement pas de HTML reçoivent ce document. Ne sont pas affectés :

- **Les navigateurs** : toute requête acceptant `text/html` affiche toujours la page d'erreur du thème
- **Les clients d'API** : les requêtes acceptant `application/json`, ou visant `/api/` et `/mcp`, conservent le corps d'erreur JSON par défaut
- **`fetch()` et `$fetch`** : les requêtes initiées par le navigateur conservent le corps d'erreur JSON par défaut, pour que `error.data` reste exploitable

Pour rétablir le corps d'erreur par défaut :

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  agentDiscovery: {
    errors: false,
  },
})
```

## Accès au Markdown brut

Docus expose un endpoint markdown brut qui permet aux agents IA de récupérer les fichiers source prêts pour les LLMs sans passer par le pipeline de rendu complet. Cela réduit l'utilisation de tokens et améliore la vitesse de réponse pour les outils IA consommant votre documentation.

### Fonctionnement

- **Endpoint** : `/raw/<chemin-contenu>.md`, le même chemin que l'URL de la page avec l'extension `.md`
- **Content-Type** : `text/markdown; charset=utf-8`, avec un en-tête `Link` pointant vers la page HTML
- **Frontmatter** : chaque document commence par son `title`, sa `description` et son `canonical_url`, et les liens de même origine sont absolus, pour qu'une page garde son sens une fois lue en dehors de votre site
- **Sections** : un chemin désignant une section plutôt qu'une page (`/raw/fr/getting-started.md`) redirige vers le premier document de cette section
- **Intégration LLMs.txt** : les liens des documents dans `llms.txt` sont automatiquement réécrits vers l'endpoint `/raw/...md`, afin que les agents récupèrent du markdown compact au lieu du HTML complet

::note{to="/raw/fr/ai/llms.md"}
Essayez d'accéder à la version Markdown brute de cette page.
::

### Configuration

Chaque page possède par défaut un jumeau markdown. Pour exclure une partie de votre site, une arborescence de pages sans équivalent markdown ou un document `.md` autonome que vous servez vous-même, étendez `excludePrefixes`. Un chemin exclu ne fait jamais l'objet de négociation, n'est listé nulle part et répond par un 404 sur l'endpoint brut :

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  agentDiscovery: {
    excludePrefixes: {
      extend: ['/admin'],
    },
  },
})
```

## Négociation Markdown

Docus sert du markdown aux agents IA et aux outils en ligne de commande qui en font la demande, sur la même URL que la page HTML.

### Pourquoi ?

Les agents comme Claude Code envoient `Accept: text/markdown` par défaut. Répondre avec du Markdown brut permet d'économiser beaucoup de transfert de données et de tokens dans le processus.

### Comment ?

Une requête reçoit du markdown quand :

- son URL se termine par `.md` : `/fr/ai/llms.md` est le jumeau markdown de `/fr/ai/llms`
- son en-tête `Accept` préfère `text/markdown` à `text/html`
- son `User-Agent` est un agent IA connu (`ClaudeBot`, `GPTBot`, `PerplexityBot` et les autres agents de la liste [ai.robots.txt](https://github.com/ai-robots-txt/ai.robots.txt))

Ensuite :

- **Chemin racine** : `/` → `/raw/index.md`, votre page d'accueil quand c'est un document de contenu, sinon un index généré de tout ce que ce site publie pour les agents
- **Pages de documentation** : `/{chemin}` → `/raw/{chemin}.md`

La négociation s'exécute en développement et sur tout hébergeur via un middleware Nitro. Sur Vercel, elle s'exécute aussi à l'edge, si bien que les pages prérendues répondent en markdown avant que le cache CDN ne voie la requête. Sur les autres hébergeurs, une page prérendue est servie avant le middleware et reste en HTML : les agents accèdent à son markdown via l'URL `.md`.

### Exemple d'utilisation

```bash
# Récupérer l'index des agents depuis la page d'accueil
curl -H "Accept: text/markdown" https://docus.dev/

# Récupérer le markdown brut d'une page de documentation
curl -H "Accept: text/markdown" https://docus.dev/fr/ai/llms

# La même page, via son URL jumelle markdown
curl https://docus.dev/fr/ai/llms.md
```

Toutes ces commandes retourneront du contenu markdown au lieu de HTML.

### Mise en cache

La même URL répond en HTML ou en markdown selon la requête, donc chaque réponse porte l'en-tête `Vary: Accept, User-Agent`. Sans lui, un CDN pourrait servir la variante HTML à un agent demandant du markdown, ou l'inverse, selon celle qui est arrivée en cache la première.

```bash
curl -sI -H "Accept: text/markdown" https://docus.dev/fr/ai/llms | grep -i vary
# vary: Accept, User-Agent
```

## Découverte

Un agent qui arrive sur votre site peut trouver tout ce qu'il publie sans lire la documentation :

- `/.well-known/api-catalog` : chaque document de service publié par ce site ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727)), également annoncé dans l'en-tête `Link` de votre page d'accueil
- `/sitemap.md` : un index markdown de toutes les pages, groupées par section, un par locale sur un site multilingue
- `/.well-known/mcp/server-card.json` : l'endpoint du [serveur MCP](/fr/ai/mcp) et les outils qu'il expose
- `/.well-known/skills/index.json` : les [Agent Skills](/fr/ai/skills) que vous publiez
- `/robots.txt` : un groupe autorisant chaque agent IA connu, avec une ligne `Content-Signal`

Tout ceci est fourni par le module [`nuxt-agent-discovery`](https://github.com/benjamincanac/nuxt-agent-discovery) et se configure sous la clé `agentDiscovery` de votre `nuxt.config.ts`.

Consultez la documentation nuxt-agent-discovery pour connaître toutes les options.
